## 결과 요약

로그인 없이 `/submit`에서 글 주소를 제보받는다. 지원 사이트(6곳)는 워커가 글 페이지를 확인해 수집과 같은 규칙으로 저장·평가한다. **DCInside는 수동 제보**로만 받는다. 제보자가 제목, 작성 시각, 내용 일부를 직접 입력하고, 서버는 DC에 접속하지 않으며, 자동 공개 없이 관리자 검토로 보낸다.

## 흐름

1. **접수 (웹, 서버 액션)**: 봇 확인(Cloudflare Turnstile) → 요청 제한(IP 해시 기준 시간당 5, 하루 20) → 주소 판별(지원 사이트 / DC 수동 / 미지원) → 입력 검증 → `submissions`에 `RECEIVED` 저장. 화면에는 "접수됐어요"만 보여 준다.
2. **처리 (워커 tick, 매분 최대 10건)**:
   - 자동: 이미 있는 글이면 중복(발견 기록만 추가), 이미 판정한 글이면 그 사유로 거절, 아니면 글 페이지 확인 → 23~03시·48시간 규칙 → 저장(경로 `USER_SUBMISSION`) → 평가 큐.
   - 수동(DC): 외부 요청 없음 → 같은 시간 규칙 → 저장(`requires_review`) → 입력 내용으로 즉시 평가 → 입력 내용 삭제.
3. **공개 결정**: `requires_review` 글은 높은 점수여도 `PUBLISHED`가 아니라 `REVIEW`. 낮은 점수는 그대로 비공개, 안전 문제는 차단.

## 실제 확인 (로컬, 2026-11-19)

| 제보 | 방법 | 결과 |
|---|---|---|
| 클리앙 실제 글 주소(이미 수집된 글) | 브라우저로 `/submit` 제출 → `npm run submissions:process` | 중복(DUPLICATE): 새 글 없이 `USER_SUBMISSION` 발견 기록 추가. 제보 설명은 저장만 되고 AI 입력에는 없음 |
| DC 테스트 주소 + 직접 쓴 테스트 문장 | 같은 방법, Gemini 평가 | 처리 완료, 68점, `REVIEW`, 입력 내용 삭제됨, 미리보기 120자만 남음. DC로 나간 요청 없음 |

- Turnstile은 개발용 Cloudflare 테스트 키로 동작(위젯이 "성공!" 표시). IP는 64자 해시로만 저장.

## 운영 시 필요한 설정

| 환경변수 | 설명 |
|---|---|
| `NEXT_PUBLIC_TURNSTILE_SITE_KEY` | Turnstile 사이트 키(빌드 시 반영). 없으면 테스트 키가 들어가 실제 비밀키와 맞지 않아 **모든 제보가 거절**됨(열리는 쪽이 아니라 닫히는 쪽으로 실패) |
| `TURNSTILE_SECRET_KEY` | Turnstile 비밀키. 운영에서 없으면 제보 접수 시 오류 |
| `IP_HASH_SALT` | IP 해시 솔트. 운영에서 없으면 제보 접수 시 오류 |

- IP는 `X-Forwarded-For` 첫 값을 쓴다. 운영에서는 리버스 프록시(Caddy)가 이 헤더를 덮어써야 한다(계획 5에서 설정).

## 알려진 제약

- DC 수동 제보의 작성 시각은 제보자 입력이라 검증할 수 없다. 그래서 항상 검토로 보낸다. **검토 화면은 계획 4**라 그전까지는 DB에 `REVIEW`로 쌓인다.
- 자동 제보에서 글 페이지의 작성 시각을 읽지 못하면 거절한다(`no_time`).
- 제보자는 처리 결과(중복·시간 밖 등)를 볼 수 없다(설계 7-10).
