## 결과 요약

조사를 통과한 6개 커뮤니티에서 실제 글을 수집해 평가 → 공개 흐름에 태운다. 개발 DB는 사용자의 로컬 PostgreSQL(다른 앱과 공유)이며, 이 앱의 모든 객체는 `sleepy` 스키마에만 있다. AI 평가는 Gemini로 실제 호출을 확인했다.

- **에펨코리아 430**: 처음엔 430을 차단으로 인식하지 못해 18개 페이지를 계속 요청했다. 이제 430을 403/429처럼 즉시 멈추고 1시간 쉰다. 에펨코리아는 회차당 글 페이지를 3개로 제한했다(`config.maxDetailFetches`).
- **Gemini 실제 평가 3건**: 클리앙(무한도전 짤 15점), 인벤(정치 녹취록 0점), 루리웹(게임 불평 15점) 모두 "서비스 성격과 다름"으로 비공개. 평범한 글을 제대로 걸러냈다.

## 최종 검토 후 수정

검토(치명 0 / 중요 5 / 사소 7)에서 나온 중요 5건과, 영향이 커서 올린 2건을 고쳤다.

- 평가 중 글 페이지가 403/429/430이면 소스를 1시간 정지하고 작업을 나중에 재시도(제목만으로 판정하지 않음). 정지 중인 소스는 수집·평가 모두 요청하지 않음.
- 수집 때 연 글 페이지를 평가에서 다시 요청하지 않음(워커 메모리에 30분 보관, DB 저장 없음).
- 평가 대기로 멈춘 글(작업 유실, 재시도 소진)을 15분 뒤 자동으로 다시 넣음. 평가 큐는 글마다 1개만.
- 계속 실패하는 글 페이지(삭제 등)는 3회 뒤 포기.
- 글 페이지에서 작성 시각을 절반 넘게 못 읽으면, 또는 여러 목록 중 하나라도 0건이면 회차를 실패로 기록(구조 변경 감지).
- 미리보기를 채운 뒤 유사 그룹을 다시 계산(제목만 같은 다른 글이 피드에서 사라지지 않게).

수정 후 워커를 실제로 한 회차(23:58 KST) 돌렸다. 에펨코리아는 앞선 보호 장치 없던 실행의 여파로 목록까지 430으로 막고 있었고, 이번에는 요청 1번 만에 멈추고 1시간 정지했다.

## 확인하지 못한 것 / 알려진 문제

- **오래된 새벽 글 (해결)**: 오늘의유머 베스트에 며칠 전 새벽 글이 올라오는 문제는 사용자 결정에 따라 "작성 후 48시간 이내만" 수집하도록 막았다(설정 `max_post_age_hours`). 결정 전에 수집된 오래된 글 몇 건은 개발 DB에 남아 있다.
- 에펨코리아는 현재 우리 봇을 430으로 막고 있다. 정지가 풀린 뒤에도 계속 막히면 5회 연속 실패로 `DEGRADED`가 된다. 사이트가 봇 요청 자체를 줄이길 원하는 것으로 보여, 상한을 더 낮추거나 수집을 끄는 결정이 필요할 수 있다.
- 최종 검토의 사소한 문제 5건은 미뤘다(시계 1분 오차 시 새벽 날짜 오류, drizzle-kit push 주의, 클리앙 시간대 없는 시각, 에펨코리아 사전 필터, Gemini 빈 응답 처리).
- 이미지 위주 글은 본문 텍스트가 없어 미리보기가 비고, AI도 제목만으로 판단한다(오늘의유머 4건 중 3건, 웃긴대학 1건).
- 워커를 실제로 밤새 돌려 본 적은 없다(수집은 CLI로 1회씩 확인).
